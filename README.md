# Заң KZ

[![CI](https://github.com/nurmukhan-20/zan-kz/actions/workflows/ci.yml/badge.svg)](https://github.com/nurmukhan-20/zan-kz/actions/workflows/ci.yml)

Қазақстан Республикасының заңдарын қарапайым тілмен іздеуге және оқуға арналған мобильді қосымша: Spring Boot сервері және React Native (Expo) қосымшасы.

> **Маңызды.** Қосымшадағы қарапайым түсіндірмелер ресми заң кеңесі болып табылмайды.
> Заң мәтіндерінің ресми дереккөзі — [adilet.zan.kz](https://adilet.zan.kz). Әр заңда дереккөз сілтемесі мен ақпараттың соңғы жаңартылған күні көрсетіледі.

## Мүмкіндіктер

- 7 категория: Конституция, қылмыстық, әкімшілік, еңбек, отбасы, салық және азаматтық құқық
- Заңдар бөлім → бөлімше → тарау → параграф құрылымымен көрсетіледі (ресми мәтіндегідей)
- Барлық мәтін үш тілде: қазақ, орыс, ағылшын
- Әр бапқа қарапайым тілмен түсіндірме
- «Менің құқықтарым» — Конституцияның II бөлімі
- Жаңалықтар таспасы: «Соңғы» және «Танымал», фото және бейне
- Ең көп оқылатын баптар (барлық пайдаланушылардың қарау тарихы бойынша)
- Заң терминдерінің сөздігі және іздеу
- Бірінші экран — кіру немесе тіркелу (тіл таңдауымен)
- USER және ADMIN рөлдері, таңдаулылар, қаралған баптар тарихы
- Заң жаңартылғанда автоматты түрде хабарлама жасалады
- Жарық және қараңғы тақырып, барлық экрандарда анимация
- **ИИ-құралдар (Google Gemini):**
  - ИИ-көмекші (чат) — базадағы баптар бойынша жауап береді және баптарға сілтеме көрсетеді; бап жоқ болса, мұны ашық айтып, жалпы ақпарат береді; сөздіктегі терминдерді түсіндіреді
  - «Менің жағдайым» — өмірлік жағдайды сипаттаса, ИИ сәйкес баптарды және не істеу керегін көрсетеді
  - Құжат жасау — демалысқа / жұмыстан шығуға өтініш, сатушыға талап-арыз, ақша қолхаты (үлгі)
  - Баптарды салыстыру — екі баптың ортақ белгілері мен айырмашылығы
  - «Заңды үйрену» тесті — таңдалған тақырыптың баптары бойынша 5 сұрақ
- **Дауыс беру:** референдумдар мен сайлаулар бюллетень сияқты — түрі, күні, атауы, не туралы екені, бюллетеньдегі сұрақ және нұсқалар (Құрылтай сайлауында — бюллетеньдегі ретпен 7 партия және «Барлығына қарсымын»). Бір пайдаланушы — бір дауыс; дауыс бергеннен кейін қосымшадағы сауалнаманың нәтижесі пайызбен көрсетіледі. Бұл ресми дауыс беру емес.
- API құжаттамасы (Swagger), Docker, GitHub Actions (CI)

## Архитектура

Сервер қабаттарға бөлінген (Layered Architecture):

```
Controller  →  Service  →  Repository  →  PostgreSQL
(REST API)    (логика)    (Spring Data)
```

| Бума | Мазмұны |
|---|---|
| `controller` | REST адрестері |
| `service` | бизнес-логика |
| `repository` | деректер қорымен жұмыс |
| `model` | кестелер (JPA entity) |
| `dto` | сұраныс және жауап объектілері |
| `security` | токенді тексеретін сүзгі |
| `config` | қауіпсіздік, Swagger, бастапқы деректер |
| `event` | оқиғалар және тыңдаушылар |
| `exception` | қателер және оларды өңдеу |

### Кестелер және байланыстар

```
Category 1 ──── * Law 1 ──── * Article
                 │  │                │
Notification * ──┘  └── * News * ────┘ (міндетті емес)

User 1 ──── * Favorite * ──── 1 Article
User 1 ──── * HistoryEntry * ──── 1 Article

Term (жеке кесте)

Poll (votings) 1 ──── * PollOption (voting_options)
Poll 1 ──── * PollVote (voting_ballots) * ──── 1 User
              (бір пайдаланушы — бір голосованиеде бір дауыс)
```

## Рөлдер

| Әрекет | Кірусіз | USER | ADMIN |
|---|---|---|---|
| Категорияларды, заңдарды, баптарды, терминдерді, хабарламаларды оқу | ✅ | ✅ | ✅ |
| Таңдаулылар және тарих | ❌ | ✅ | ✅ |
| ИИ-құралдар, дауыс беру | ❌ | ✅ | ✅ |
| Қосу, өзгерту, жою (оның ішінде жаңа дауыс беру) | ❌ | ❌ | ✅ |

Тіркелу арқылы тек USER рөлін алуға болады. Әкімші (ADMIN) сервер іске қосылғанда `local.properties` файлындағы деректер бойынша жасалады.

### ИИ қалай жұмыс істейді

1. Сервер сұрақтағы сөздер бойынша базадан ең сәйкес баптарды табады (`AssistantService`).
2. Табылған баптар мәтінімен бірге Gemini-ге жіберіледі: «тек осы баптар бойынша жауап бер».
3. Жауапта қолданылған баптардың id-і қайтарылады — қосымша оларды батырма ретінде көрсетеді.
4. Gemini кілті тек серверде (`local.properties`) сақталады, қосымшаға берілмейді. Gemini бос емес болса (503), сервер автоматты түрде тағы 2 рет қайталайды (`GeminiClient`).

## Жобалау үлгілері (Design Patterns)

1. **Repository.** Деректер қорымен жұмыс `CategoryRepository`, `LawRepository`, `ArticleRepository` т.б. интерфейстерге бөлінген. Сервистер SQL жазбайды, тек репозиторийді шақырады. Деректер қорын ауыстырса, сервистер өзгермейді.

2. **Observer (бақылаушы).** Әкімші заңды өзгерткенде `LawService` тек `LawUpdatedEvent` оқиғасын жариялайды. Оны `LawUpdatedListener` тыңдап, барлық пайдаланушыларға хабарлама жасайды. Заң сервисі хабарламалар туралы ештеңе білмейді, сондықтан жаңа реакция қосу үшін (мысалы, email) тек жаңа тыңдаушы жазу жеткілікті. Тест: `LawServiceTest`.

3. **DTO (Data Transfer Object).** `RegisterRequest`, `AuthResponse`, `FavoriteResponse` т.б. Пайдаланушы кестесі сыртқа берілмейді, сондықтан құпиясөз хэші мен токен жауапқа түспейді.

4. **Dependency Injection.** Барлық тәуелділіктер конструктор арқылы беріледі. Бұл тесттерде нақты деректер қорының орнына Mockito бүркеншіктерін қоюға мүмкіндік береді.

## Іске қосу

### 1-нұсқа: Docker (ең оңай)

Қажет: [Docker Desktop](https://www.docker.com/products/docker-desktop/).

1. Жобаның түбірінде `.env.example` файлын `.env` деп көшіріп, құпиясөздерді жазу (`.env` GitHub-қа жүктелмейді).
2. Іске қосу:
```
   docker compose up --build
```
3. Тексеру: `http://localhost:8080/swagger-ui.html`

Сервер мен PostgreSQL бірге іске қосылады, деректер `zankz-data` томында сақталады. Тоқтату: `Ctrl+C` немесе `docker compose down`.

### 2-нұсқа: қолмен

Қажет: Java 21, PostgreSQL, Git.

1. Репозиторийді жүктеу:
```
   git clone https://github.com/nurmukhan-20/zan-kz.git
   cd zan-kz/server
```

2. PostgreSQL-да `zankz` деректер қорын жасау.

3. `server` бумасында `local.properties` файлын жасау (бұл файл GitHub-қа жүктелмейді):
```properties
   spring.datasource.password=POSTGRES_ҚҰПИЯСӨЗІ
   app.admin.email=admin@zankz.kz
   app.admin.password=ӘКІМШІ_ҚҰПИЯСӨЗІ
   # ИИ-құралдар үшін (міндетті емес): кілтті https://aistudio.google.com/apikey сайтынан алуға болады
   app.gemini.key=GEMINI_КІЛТІ
   app.gemini.model=gemini-3.6-flash
```
   Кілт жазылмаса, қосымша толық жұмыс істейді, тек ИИ-құралдар «ИИ-помощник не настроен» деп жауап береді.

4. Серверді іске қосу:
```
   .\mvnw.cmd spring-boot:run
```
   (Linux/macOS: `./mvnw spring-boot:run`)

5. Тексеру:
   - `http://localhost:8080/api/categories`
   - `http://localhost:8080/swagger-ui.html`

Бірінші іске қосқанда кестелер автоматты түрде жасалады және бастапқы деректер (категориялар, заңдар, терминдер, жаңалықтар) толтырылады.

### Мобильді қосымша

Қажет: Node.js, телефонда Expo Go.

1. `app/src/api.js` файлында `LAPTOP_IP` — компьютердің IP мекенжайы (`ipconfig` → IPv4).
2. Іске қосу:
```
   cd app
   npm install
   npx expo start -c
```
3. Телефонда Expo Go арқылы QR-кодты сканерлеу. Телефон мен компьютер бір Wi-Fi желісінде болуы керек.

### Тесттер

```
.\mvnw.cmd test
```

Тесттер деректер қорынсыз жұмыс істейді (Mockito).

### CI (GitHub Actions)

Әр `git push` кейін GitHub автоматты түрде тексереді:
1. сервер жиналады және барлық тесттер өтеді;
2. қосымшаның JS-бумасы жиналады (`expo export`);
3. серверден Docker-образ жиналады.

Нәтиже: репозиторийдегі **Actions** қойындысы және README басындағы белгі.
